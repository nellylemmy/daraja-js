# daraja-js 1.5.0 — Transaction Status by OriginatorConversationID, B2C v3, initiator-credential codes — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@kepas/daraja-js` 1.5.0 so a caller can (a) query a transaction's status by its OriginatorConversationID when no receipt exists, (b) send B2C with a caller-generated OriginatorConversationID through the B2C v3 endpoint, (c) read `transactionStatus` and `receipt` off a parsed status result without touching `params`, and (d) get catalogued meanings for the initiator-credential codes 2001 and 8006 on `b2c` and `b2b`.

**Architecture:** Four additive changes inside the existing resource modules (`src/resources/status.ts`, `src/resources/b2c.ts`, `src/result-codes.ts`). No new modules, no new error classes, no behaviour change for existing inputs: `status.transaction({ transactionId })` and `b2c.send` without `originatorConversationId` produce byte-identical request bodies to 1.4.1. Every wire shape is pinned by an MSW test that captures the body.

**Tech Stack:** TypeScript strict, ESM + CJS via tsup, vitest + msw for unit tests, biome for lint/format, changesets for versioning, commitlint (Conventional Commits) and DCO sign-off (`git commit -s`).

**Spec:** `/Users/ADEA/Documents/development/daraja-studio/docs/superpowers/specs/2026-09-06-phase-2a-money-out-design.md` §4 (the consumer's requirements), plus this repo's `docs/specs/*.md` proof documents.
